## Helper Methods (add to `RewardConstraintConcurrencyIntegrationTest`)

The following helpers are referenced by DA-01 through DA-07 and T9. Add them to the test class before the first `@Test` method:

```java
import java.util.Calendar;
import java.util.TimeZone;

/** Asserts stored ISSUE_DATE has no time component (midnight in UTC). */
private void assertMidnight(Date date) {
    Calendar cal = Calendar.getInstance(TimeZone.getTimeZone("UTC"));
    cal.setTime(date);
    assertEquals(0, cal.get(Calendar.HOUR_OF_DAY),
        "ISSUE_DATE hour must be 0 — non-midnight date indicates time-stripping bug in writeNonOrgSummariesAtomically");
    assertEquals(0, cal.get(Calendar.MINUTE),   "ISSUE_DATE minute must be 0");
    assertEquals(0, cal.get(Calendar.SECOND),   "ISSUE_DATE second must be 0");
}

/**
 * Asserts no two rows share the same calendar date with different stored timestamps.
 * Guards against the non-midnight duplicate-row bug observed in production (2026-06-24):
 * one row at 11:25:57 + one row at 00:00:00 = same logical row, two DB rows.
 */
private void assertNoDuplicateIssueDates(List<RewardIssueSummary> rows) {
    Map<String, Long> dateCount = rows.stream().collect(
        Collectors.groupingBy(
            r -> {
                Calendar c = Calendar.getInstance(TimeZone.getTimeZone("UTC"));
                c.setTime(r.getIssueDate());
                return c.get(Calendar.YEAR) + "-" + c.get(Calendar.DAY_OF_YEAR);
            },
            Collectors.counting()
        )
    );
    dateCount.forEach((day, count) ->
        assertEquals(1L, count,
            "More than 1 row for calendar date " + day
            + " — non-midnight duplicate row bug detected. "
            + "Fix: DATE(ISSUE_DATE) = DATE(:date) in findExistingForNonOrgLevel SQL"));
}
```
