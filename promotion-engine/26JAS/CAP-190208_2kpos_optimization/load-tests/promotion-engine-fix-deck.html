The Problem

Before the fix, each evaluate() request walked the entire active POS promotion set — matching, then running redemption restrictions on, all of them.

Root Cause

No shortlisting — work ∝ catalog size

Before (pre-fix)

  • Evaluate all 5,000 active POS promotions
  • Run 5,000 customer redemption checks
  • Latency: 46s avg, p95 63s, p99 79s
  • Collapses at 50 RPM on 8 pods

After (fix)

  • Shortlist to ~24 promotions matching the cart's SKUs
  • Run ~24 customer redemption checks
  • Latency: 0.25s avg, p95 0.34s, p99 0.42s
  • Holds 2,000 RPM at 100% success

The fix (PR #866) adds SKU-based shortlisting: only promotions whose SKU conditions match the cart items proceed to restriction evaluation.

The Fix

SKU-based shortlisting — work ∝ cart size

Before evaluating restrictions, the engine filters the active promotion set down to the ones whose SKU conditions match the cart. The heavy per-request work now tracks what's in the cart, not the size of the catalog.

How the fix works · Tech

ItemBasedShortlisting — a purely subtractive filter

A new ItemBasedShortlistingService runs first in the shortlisting pipeline (before the costlier DB-backed filters). It recursively walks each promotion's condition tree and collects every SKU IN (…) criterion.

Dropped only when…

  • Promotion has a SKU IN condition
  • AND the cart's SKU set intersects none of its required SKUs
  • → no required SKU present in cart

Always passed through

  • Category / brand / attribute promotions (no SKU-IN)
  • Cart-based & payment-mode promotions
  • Null / empty condition
  • Feature flag off, or cart has no SKUs

The filter is purely subtractive on SKU-IN conditions only — anything without an explicit SKU-IN constraint is untouched and proceeds to full evaluation.

How the fix works · Tech

Non-SKU promotions are never dropped

The guard is an early return in the exclusion check — a promotion with no SKU-IN criterion is kept, always:

if (skuInCriteria.isEmpty()) {
  return false; // no SKU-IN constraint (category/brand/attribute/cart-only) — pass through
}
return skuInCriteria.stream().noneMatch(c ->
  !CollectionUtils.isEmpty(c.getValues()) && !Collections.disjoint(c.getValues(), cartSkuSet));

Gated rollout

Enabled per-org via ITEM_BASED_SHORTLISTING_ENABLED_ORG_IDS — org 50223 on the allowlist

Safe fallback

Flag off or no cart SKUs → full pass-through, zero behavior change

Correctness

Only SKU-IN promotions are ever excluded; all other types always evaluate
